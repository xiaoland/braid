# Codex app-server Protocol

This adapter targets the schema generated by the installed Codex binary, not a
hand-maintained protocol copy. The first verified version is
`codex-cli 0.147.0-alpha.6.5`; its stable v2 schema bundle has SHA-256
`7d79fe309dd7520843459070f3884ecf0e39cee2620c1c49aad6efb4eca76ecb`.
The experimental bundle required for Wrapper-origin application context has
SHA-256 `a14d4878fe7b8cdd31059dbca11d7167d8cfd06effa2f7991b5364439063a5c8`.
Executable schemas remain the authority when a later binary changes.

## Wire and Lifecycle

- stdio carries one JSON object per line. The Codex protocol deliberately omits
  the JSON-RPC `jsonrpc` member on the wire.
- A connection sends `initialize`, waits for its response, then sends the
  one-way `initialized` notification. Thread methods before initialization
  fail. Braid opts into `capabilities.experimentalApi`; absence or drift is a
  startup failure.
- `thread/start` creates the provider-owned thread. `thread/resume` addresses
  that same thread after transport restart; the probe completes a turn before
  relying on a materialized rollout.
- `turn/start` returns an in-progress turn handle. Live items arrive through
  notifications, and only `turn/completed` is terminal. Its status is one of
  `completed`, `interrupted`, `failed`, or `inProgress`; an `error` notification
  may be retryable and is not itself terminal.
- `turn/steer` has an `expectedTurnId` precondition. `turn/interrupt` must target
  the active turn; no active turn is a protocol error.
- Wrapper-origin wake references use experimental `additionalContext` entries
  with `kind: application`. Each request also carries one fixed non-Human,
  non-command trigger text because the installed protocol requires non-empty
  `input`. The application entry contains only typed event/ref data; GitHub
  prose remains canonical state that the Agent fetches with `gh`.

The official app-server README documents the general lifecycle, while exact
fields and compatibility are pinned from `generate-json-schema` against the
local binary: <https://github.com/openai/codex/blob/main/codex-rs/app-server/README.md>.

## Projection Boundary

`item/completed` is the authoritative item snapshot and deltas are provisional.
The provider adapter passes supported item snapshots to the semantic reducer;
it does not persist or reconstruct the provider transcript, own compaction, or
infer task success from a terminal status. The complete admission, rendering,
bounds, batching, and recovery contract is the dedicated
[turn projection document](turn-projection.md).

## Executable Probe

Run the probe from the independent project:

```shell
pdm run braid probe-app-server \
  --codex /absolute/path/to/codex \
  --workspace /absolute/path/to/a/read-only-probe-directory
```

The command generates and digests the installed stable schema, starts a
persistent read-only thread, observes completion, proves completed-turn steer
rejection and active-turn steering, interrupts a turn, observes a real failed
terminal state, disconnects during an active turn, restarts the stdio process,
confirms provider-side interruption, resumes the same thread, and runs a final
turn. It also proves Wrapper-origin `application` context with the fixed,
explicitly non-Human trigger. Any missing method, unknown status, response
mismatch, timeout, or wrong final projection fails the command.
